# 「驿」路同行 · 微信小程序架构设计方案

> 对接对象：`ldl-platform` 现有 Cloudflare Workers + D1 后端，专用接口前缀 `/api/mp/*`
> 设计目标：**快速上线 + 低成本获客**，复用已建后端，不重造轮子
> 文档性质：架构设计 + 可运行脚手架说明 + 上线合规清单

---

## 0. 现状速读（决定了架构思路）

- 后端：基于 Cloudflare Workers + D1，CORS 已放开 `*`，HTTPS 已具备。
- 小程序接口 `/api/mp/*` 已完备：增量同步 `sync`、列表/搜索、详情、附近、枚举、统计、版本探测、匿名反馈。
- 数据模型：驿站（名称/地址/区域/经纬度/设施/状态/开放时间/容量），坐标体系 **gcj02**（与微信地图一致）。
- 写操作（增删改状态）需 `X-Admin-Token`，**严禁下发到小程序**——小程序侧只读 + 匿名反馈即可。

**结论**：小程序不需要自建后端/云开发，纯前端对接即可，这是"快速上线"的最大杠杆。

---

## 1. 产品定位与获客策略（用户最关心的部分）

这是一个 **LBS 公益服务小程序**，核心闭环：发现附近驿站 → 导航前往 → 留言反馈 → 分享扩散。

### 获客四大引擎（按性价比排序）

| 优先级 | 渠道 | 做法 | 为什么适合本项目 |
|---|---|---|---|
| ★★★ | **线下扫码** | 每个驿站贴「歇脚指南」时附小程序码，`path=/pages/detail/detail?id=XX` 直达该驿站 | 物理触点 × 微信扫一扫，转化最高；且你们本就要去驿站贴标，零额外成本 |
| ★★★ | **社交裂变** | `onShareAppMessage`（分享给好友/群）+ `onShareTimeline`（分享朋友圈） | 公益主题天然适合转发，文案已内置 |
| ★★ | **订阅消息** | 留言提交后 `wx.requestSubscribeMessage` 申请「处理进度/附近新增驿站」通知 | 一次授权，后续主动触达，拉回流 |
| ★★ | **内容导流** | 绑定公众号（文章嵌入小程序卡片）+ 视频号挂载 | 把长文/短视频流量导进小程序 |

> 补充：小程序类目建议选「工具-地图导航」或「生活服务-便民服务」，搜索（搜一搜）与"附近的小程序"可带来自然流量。

## 2. 技术选型

| 维度 | 决策 | 理由 |
|---|---|---|
| 开发框架 | **原生小程序**（WXML/WXSS/JS） | 零构建、上手快、最贴合微信能力、审核最稳 |
| 后端 | **复用现有 Workers**，不引入云开发 | 接口已就绪，省掉后端开发与运维 |
| 地图 | **微信原生 `<map>` + `wx.openLocation`** | 免高德 Key、坐标体系一致、导航唤起系统地图，稳定可靠 |
| 状态管理 | `app.globalData` + `Storage` 缓存 | 数据量小（几十~几百条），无需 MobX |
| 网络层 | 统一 `utils/request.js`（Promise + 信封解析 + 失败重试 1 次） | 所有接口判 `res.data.ok`，失败弹 `message` |
| 数据同步 | `utils/sync.js` 增量同步 + 版本探测 + 离线兜底 | 直接吃后端 `sync` 接口设计，省流量且实时 |

## 4. 数据层：增量同步（性能与离线关键）

后端 `sync` 接口设计就是为小程序增量同步准备的，脚手架已落地完整策略：

1. **首次启动**：`since=0` 拉全量 → 写本地 `Storage`（key `mp_stations_cache`）。
2. **日常/下拉刷新**：先调 `/api/mp/version` 比对 `latest_updated_at`，**无变化直接读缓存**；有变化再 `sync?since=<上次server_time>` 拉增量，按 `id` Upsert，`is_deleted=true` 则本地删除。
3. **离线兜底**：网络失败时用 `getCachedStations()` 展示本地数据，体验不崩。

> 数据量小，用 `Storage` 足够；若未来破千条，可平滑迁移到 `wx.getFileSystemManager` 或本地数据库（如 `weappx`）。

## 6. 地图与定位（合规要点）

- 用 `wx.getLocation({ type: 'gcj02' })`，与后端坐标一致。
- 必须在 `app.json` 声明：
  ```json
  "permission": { "scope.userLocation": { "desc": "用于查找离您最近的歇脚驿站并提供步行导航" } },
  "requiredPrivateInfos": ["getLocation"]
  ```
- 用户拒绝定位时**优雅降级**：切到「全部」列表（按区域），不阻断使用。
- 导航用 `wx.openLocation` 唤起系统地图，步行路线体验好，且无需第三方地图 Key。

## 7. 性能与包体积

- 主包当前约 **< 200KB**，远低于 2MB 上限，**暂不需要分包**。
- 已开启 `lazyCodeLoading: "requiredComponents"`，首屏只加载用到的组件。
- `setData` 仅传视图所需字段；列表渲染用 `wx:for` + `wx:key`，数据量大时可后续上虚拟列表。
- 图片走 CDN（如后续加驿站照片，建议 WebP + 懒加载）。

## 8. 合规与审核清单（避坑）

| 项 | 要求 | 状态/动作 |
|---|---|---|
| **request 合法域名** | 微信后台 → 开发设置 → 服务器域名 → request 合法域名 添加你的 Workers URL | 必做，真机/发布前配置，约 5 分钟生效 |
| **AppID** | `project.config.json` 的 `touristappid` 仅限开发者工具游客模式；发布需替换为你自己的小程序 AppID | 必换 |
| **隐私政策** | 微信后台配置《隐私保护指引》URL；敏感接口（位置）需用户授权弹窗（代码已用 `wx.requirePrivacyAuthorize` 兜底） | 必配 |
| **类目选择** | 选「工具-地图导航」或「生活服务-便民服务」，与功能一致，避免类目不符被拒 | 必选 |
| **内容合规** | 公益属性，无 UGC 未审核内容；反馈走 `msgSecCheck` 可在后端补充（当前匿名提交，建议后端加内容安全校验） | 建议后端补 |
| **无违规诱导分享** | 分享为自愿行为，文案无"集赞/强制分享"字样 | 已注意 |

## 9. 上线 5 步清单

1. **注册/复用小程序账号**：拿到自己的 AppID，填进 `project.config.json`。
2. **配置域名白名单**：request 合法域名加你的 Workers URL。
3. **配置隐私政策 + 位置权限说明**：后台填《隐私保护指引》，确认 `app.json` 已声明定位权限。
4. **开发者工具预览/真机调试**：游客模式可直接跑（已用 `touristappid`）；真机预览需先完成 1–2 步。
5. **提交审核**：类目选对、截图清晰、功能自测通过 → 提交 → 关注审核意见补材料。

> 预估：后端已就绪、脚手架可直接运行，**最快 1–2 天可提交审核**。

## 10. 后续演进（不发版也能迭代）

- **分包**：若加「志愿者报名」「科普文章」等模块，再拆 `subpackages/`。
- **Skyline 渲染**：列表/地图动画升级，体验更接近原生 App。
- **订阅消息模板**：后台申请模板后填 `feedback.js` 的 `tmplId`，实现留言闭环通知。
- **线下码体系**：为每个驿站生成带 `id` 的小程序码（服务端 `getwxacode` 或后台生成），贴到实体「歇脚指南」上，形成最强获客闭环。
- **管理端小程序**（可选）：用同一套后端，给项目组做状态更新/审核反馈的轻量管理端。
